# Mobile Application Host Shells

Last reviewed: 2026-11-01

## Scope and evidence

This repository now has minimal native application host targets for Android and iOS. They validate application packaging and lifecycle entry points; they are not yet runnable game environments.

| Platform | Artifact | CI evidence | Current boundary |
|---|---|---|---|
| Android | arm64-v8a debug APK | Gradle assembleDebug and APK contents checked by GitHub Actions | NativeActivity lifecycle bridge only; no rendering, touch input, integrated GameLoop, or game content |
| iOS | unsigned arm64 device .app bundle | CMake/Xcode app target and output bundle checked by GitHub Actions | UIKit scene lifecycle host only; no signed app, renderer, integrated GameLoop, archive, or IPA |

No physical device or emulator execution has been performed. Neither platform is Verified.

## Android host

The Gradle project is under `platforms/android`.

Toolchain selected for the host build:

- JDK 17
- Gradle 9.6.0
- Android Gradle Plugin 9.4.0
- Android SDK 36 / Build Tools 36.0.0
- Android NDK 28.2.13676358
- CMake 3.31.0
- arm64-v8a
- minSdk 21 and targetSdk 36 for this host package

Build a debug APK after installing those SDK packages and Gradle:

```sh
gradle -p platforms/android :app:assembleDebug
```

Expected artifact:

```text
platforms/android/app/build/outputs/apk/debug/app-debug.apk
```

The manifest launches `android.app.NativeActivity` and loads `storm_android_native_activity`. The native entry point currently handles NativeActivity lifecycle and surface metadata through the existing adapter. It does not run `MobileFrameDriver`, render pixels, process touch input, or export a game. The APK is a development host shell only; release signing, AAB generation, icon/splash configuration, and wider ABI support remain planned.

## iOS host

The iOS host target is `storm_ios_app`, generated by the root CMake project. It uses the existing `StormEngineSceneDelegate` lifecycle adapter and a small status screen to make the host-shell boundary explicit.

Build the unsigned device app bundle on macOS with Xcode and the iOS SDK:

```sh
cmake -S . -B build-ios-arm64 -G Xcode \
  -DCMAKE_SYSTEM_NAME=iOS \
  -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=13.0 \
  -DSTORMENGINE_BUILD_TESTS=OFF \
  -DCMAKE_BUILD_TYPE=Release

cmake --build build-ios-arm64 --config Release --target storm_ios_app
```

Expected bundle:

```text
build-ios-arm64/Release-iphoneos/storm_ios_app.app
```

Code signing is disabled for CI. There is no provisioning profile, archive, IPA, or distribution workflow. The app host does not initialize the game loop or renderer.

## Security and compatibility notes

- Signing certificates, provisioning profiles, keystores, and private keys must remain outside the repository.
- The Android package is restricted to arm64-v8a for this first build target; this is not support for every Android device.
- The iOS app target uses iOS 13.0 because the existing scene lifecycle adapter is based on `UIWindowSceneDelegate`.
- The host package SDK/deployment settings are build configuration, not a complete engine compatibility policy.
- Successful packaging proves build integration only. Lifecycle behavior, frame pacing, surface recreation, input, graphics, thermal behavior, and battery behavior still require simulator/device tests.
